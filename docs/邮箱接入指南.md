# 邮箱接入指南（连接你自己的邮箱，不限于飞书）

> 一句话结论：**系统只依赖标准 IMAP/SMTP**，飞书只是内置预设里的一个选项。
> 腾讯企业邮、阿里云、网易、Gmail、Microsoft 365、Zoho、自建 Postfix/Dovecot 都能接，
> 而且**全部可以在图形界面里配置**（超级管理员 → 邮箱配置），不需要改代码、不需要改配置文件。

---

## 1. 接入原理：为什么要 IMAP + SMTP 两套

```text
        ┌──────────── 你的邮箱服务商（任何一家）────────────┐
        │   IMAP 服务器（收信）        SMTP 服务器（发信）   │
        └───────▲──────────────────────────────┬──────────┘
                │ ① 定时增量拉取                │ ④ 以组身份投递
    apps/mailboxes/imap_client.py        apps/mailboxes/services.py::smtp_send
        │  (标准 IMAP4，SSL 或 STARTTLS)      │  (smtplib，隐式 TLS 或 STARTTLS)
        │                                      │
    apps/mailboxes/sync.py  ← 由 runapscheduler 每 N 秒轮询
        ↓
    apps/mailboxes/pipeline.py（防循环 → 归并 → 路由 → 落库 → 自动回复）
```

- **收信**：`apps/mailboxes/imap_client.py::connect_imap()` 连接 → 加密 → 登录，
  `apps/mailboxes/sync.py::sync_mailbox()` 按 `UIDVALIDITY`/`last_uid` 做增量拉取（只拉 INBOX 的新邮件）。
- **发信**：`apps/mailboxes/services.py::smtp_send()`，隐式 TLS（465）或 STARTTLS（587/25）。
- 两者都只吃"主机 / 端口 / 加密方式 / 账号 / 密码"，**没有任何服务商专属 API**。
  代码里唯一出现"飞书"的地方是内置预设的默认主机名与文档措辞。

## 2. 图形化接入步骤（无需改配置文件）

| 步骤 | 界面位置 | 说明 |
|---|---|---|
| 1 | 用**超级管理员**登录 | 邮箱配置是 §2.7 里的超管职责（凭据是全系统最敏感的信息） |
| 2 | 左侧「系统 → 邮箱配置」→「新建邮箱」 | 路径 `/accounts/mailboxes/new/` |
| 3 | 选择**服务商预设** | 下拉里选你的服务商，IMAP/SMTP 主机、端口、加密方式**自动填好**，并显示该服务商的授权码获取方法 |
| 4 | 填「邮箱地址」与「登录账号」 | 通常是完整邮箱地址本身（如 `support@yourcorp.com`） |
| 5 | 填「授权码 / 密码」 | 多数服务商要求用**授权码/应用专用密码**而不是网页登录密码；保存后以 Fernet 密文入库，页面永不回显 |
| 6 | 保存后点该行的「连通性检查」 | 只做**只读**探测：IMAP 登录 + 选中 INBOX 数邮件、SMTP 登录后立即退出；**绝不发送任何邮件** |
| 7 | 到「系统 → 用户组管理」把该邮箱绑定给用户组 | 组邮箱用于"以组身份收发信"；无邮箱组自动走全局兜底邮箱 |

补充说明：

- 若你的服务商不在预设里，选「自定义 / 其他服务商」全部手填即可——**预设只是便利，不是白名单**。
- 端口留空会用预设端口，没有预设则用默认值（IMAP 993 / SMTP 465）。
- 演示数据（`manage.py seed_demo`）里的主机名是 `imap.example.com` 占位，请替换为真实值。

## 4. 加密策略：SSL 与 STARTTLS

模型里只有 `imap_ssl` / `smtp_ssl` 两个开关，用它表达两类安全连接：

| 开关 | 行为 | 常用端口 |
|---|---|---|
| 勾选「使用 SSL」 | **隐式 TLS**：连接建立即加密 | IMAP 993 / SMTP 465 |
| 取消勾选 | 明文连接后**强制升级 STARTTLS** 再登录；服务器不支持 STARTTLS 时**直接报错** | IMAP 143 / SMTP 587 |

关键安全约束：**关闭 SSL 不会导致凭据明文过网**——如果服务器不支持 STARTTLS，
连接会失败并提示（`apps/mailboxes/imap_client.py`），而不是退回明文登录。
界面上「连通性检查」与定时同步走的是**同一个** `connect_imap()`，因此不会出现"检查通过、同步失败"的偏差。

## 5. 「连通性检查」到底做了什么

| 做 | 不做 |
|---|---|
| IMAP：`connect_imap()` 建连、按策略加密、`LOGIN`、`SELECT INBOX` 并返回邮件数 | ❌ 不读取任何邮件内容 |
| SMTP：`SMTP_SSL`/`SMTP` 建连、`LOGIN`、`QUIT` | ❌ **绝不调用 sendmail/send_message**，不会给任何人发信 |
| 失败时把可读原因（含是否支持 STARTTLS、认证失败等）显示在页面上，并记日志（凭据被替换为 `***`） | ❌ 不在此处修改任何邮箱状态、不动 `last_uid` |

## 6. 多个邮箱如何对应业务（§2.1）

| 邮箱 | 是否对外公开 | 在系统里的角色 |
|---|---|---|
| 统一进线邮箱 | 是 | 首次进线入口，来信按"粘性 → 规则 → 兜底组 → 管理员组"路由 |
| 组专用邮箱 | 是 | 该组对外收发信身份；来信**直接进入该组** |
| 全局兜底邮箱 | 是 | 全局唯一；无邮箱组的对外回信都由它发出 |
| 管理员组邮箱 | 是 | 管理员组的对外身份 |

判定规则：**邮箱绑定到某个组**（`Group.mailbox`）= 组专用邮箱；`is_fallback=True` = 全局兜底；两者都不是 = 统一进线邮箱。

## 7. 权限：谁能配置邮箱

| 操作 | 超级管理员 | 组内管理员 | 管理员组成员 | 普通组员 |
|---|---|---|---|---|
| 查看邮箱列表 / 新建 / 编辑 / 连通性检查 | ✅ | ✅ | ✅ | ❌ 403 |
| 用户管理、用户组管理 | ✅ | ❌ 403 | ❌ 403 | ❌ 403 |
| Django Admin 里的 `Mailbox` | ✅（staff） | ❌ | ❌ | ❌ |

**2026-09 的人工决定**：邮箱配置从"仅超级管理员"放开到**所有可跨组查看的管理者**
（组内管理员 + 管理员组成员），这样各业务组可以自行维护本组邮箱；
用户/用户组管理**仍只属于超级管理员**，两者已解耦（装饰器 `mailbox_admin_required`
与 `superadmin_required` 分开，见 `apps/core/permissions.py`）。

**放权的代价与对策**（务必知悉）：

| 风险 | 现状与对策 |
|---|---|
| 能配邮箱 = 能看到/修改**所有**邮箱的主机、端口、账号，并能更新凭据 | 凭据仍只写不读（页面永不回显明文，密文存储）；**新建/编辑/换凭据都会写审计**（`event=mailbox_created/mailbox_updated`，记录改动字段名与"是否更新凭据"布尔值，绝不记录明文） |
| 误改统一/兜底邮箱会影响全系统收发信 | 兜底邮箱仍全局唯一（模型层校验）；建议只把"管理员组"身份给真正需要的少数人 |
| 需要"只能管本组邮箱"的更细粒度 | 尚未实现。若需要，可在 `mailbox_admin_required` 内收窄为"按邮箱绑定组校验"，属权限策略变更，需确认 |

审计入口：`/audit/` 按动作 `配置变更` 筛选，或直接看工单无关的 `config_change` 记录。

## 8. 已知限制（诚实清单）

| 限制 | 影响 | 现状与替代方案 |
|---|---|---|
| **不支持 OAuth2 / XOAUTH2**（已确认暂不实现） | Microsoft 365（默认已停用 IMAP/SMTP 基础认证）、强制 OAuth 的 Google Workspace 组织无法直接用账号密码接入 | 走"应用专用密码 / 启用 SMTP AUTH"这条路即可接入，**不需要改代码**：<br>① **Microsoft 365**：管理员在该邮箱的邮箱策略里启用 SMTP AUTH（PowerShell：`Set-CasMailbox -Identity user@contoso.com -SmtpClientAuthenticationDisabled $false`，或安全默认值关闭后逐账号开放），然后为该账号建立应用密码填到凭据里；<br>② **Google Workspace**：开启两步验证 → 生成**应用专用密码**（若组织策略禁用了"不够安全的应用/应用密码"，需管理员放开或改用下面的中继）；<br>③ **兜底方案**：在本机跑一个支持 OAuth 的 IMAP/SMTP 中继（用 OAuth 连服务商、对内向本系统暴露普通密码认证），系统侧仍然按标准 IMAP/SMTP 接。<br>若将来必须原生支持 OAuth2，需要新增字段存 refresh token 与授权流程（§10.4 需人工确认）。 |
| 只同步 `INBOX` | 其他文件夹（归档、垃圾箱）的邮件不生成工单 | 需要多文件夹时可在 `sync.py` 扩展文件夹列表 |
| 每个邮箱一个账号 | 不做共享邮箱/代理访问 | 用"组邮箱 + 组内共享"的方式替代 |
| 部分服务商要求 `IMAP ID` 客户端标识（如网易） | 连接被拒 | 优先使用企业邮箱；如需支持可在 `connect_imap()` 中补 `ID` 命令 |
| 授权码轮换后需重录 | 轮换后同步与发信会报认证失败 | 界面上编辑邮箱、重填凭据即可；`FERNET_KEY` 丢失也需重录 |

## 9. 常见故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 检查报「IMAP 登录失败」 | 用了网页登录密码而非授权码；IMAP 服务未开启；账号被限制 | 到服务商后台开启 IMAP/SMTP 并生成授权码；确认用户名是完整邮箱 |
| 检查报「未提供 STARTTLS」 | 端口填了 143/587 但服务器不支持 STARTTLS，或防火墙拦了加密协商 | 改用 SSL 端口（993/465）；或确认服务商支持 STARTTLS |
| 检查报「无法连接 IMAP 服务器」 | 主机名/端口错；出网被防火墙拦截；证书校验失败 | 用 `openssl s_client -connect host:993` 验证可达性；自建服务器请用受信任证书 |
| M365 报认证失败 | 微软已停用基础认证 | 让管理员启用 SMTP AUTH 并创建应用密码，或见 §8 的 OAuth 说明 |
| Gmail 报认证失败 | 未开启两步验证 / 未生成应用专用密码 | 开启两步验证 → 生成应用密码 → 用它作为凭据 |
| 同步正常但发不出信 | 该组没绑邮箱且未配置全局兜底邮箱 | 「用户组管理」绑定邮箱，或「系统设置」指定兜底邮箱 |
| 收到重复工单 | 邮箱被多处同步 / UIDVALIDITY 变化 | 系统已用 `Message-ID` 幂等去重（`pipeline.already_seen`）；确认同一邮箱只配置一次 |
| 一直停在「最后同步位点 0」 | 调度器未运行 | 检查 `scheduler` 容器 / `manage.py runapscheduler` 是否在跑 |

## 10. 不使用界面时的验证方式（排障用）

```bash
# 1) 改完配置后让调度器立刻跑一轮（不启动常驻进程）
cd /srv/ticket-system/app
.venv/bin/python manage.py runapscheduler --once

# 2) 直接测某个邮箱的 IMAP 可达性（不出网环境请忽略）
.venv/bin/python - <<'PY'
import os, django
os.environ.setdefault("DJANGO_SETTINGS_MODULE", "config.settings")
django.setup()
from apps.accounts.models import Mailbox
from apps.mailboxes.imap_client import connect_imap
mailbox = Mailbox.objects.get(email="support@yourcorp.com")
with connect_imap(mailbox, mailbox.get_secret()) as client:
    print("INBOX 状态:", client.select_folder("INBOX"))
PY
```

测试覆盖：`tests/test_mailbox_connection.py`（服务商预设数据、SSL/STARTTLS 策略、明文拒绝、
连通性检查不 500 且不发信、界面只选预设即可保存）、`tests/test_sync.py`（增量位点语义）。
