### 与文档伪代码的 14 处偏差

全部记录在 `docs/需求实现对照.md` 第 3 节（DEV-1 ~ DEV-14），其中影响正确性的关键三处：

1. **DEV-2**：§6.5 伪代码在"建单后"才判断首次进线，会导致自动回复**永不触发**；实现改为用归并结果
   在建单前判断（与 §2.4 语义和 §12.3 用例一致）。
2. **DEV-4**：MariaDB/MySQL 会**静默跳过**带 `condition` 的 `UniqueConstraint`（已用 Django 5.2 源码
   `_unique_supported()` 复核），"全局唯一兜底邮箱""全局唯一模板"改由模型层 `clean()/save()` 保证。
3. **DEV-5**：§6.4 伪代码无条件推进 `last_uid`，会永久跳过处理失败的邮件；实现只推进到连续成功
   的最后一封，并增加 Message-ID 幂等去重。

## 3.1 v1.2 增量：规则打标签（add_tag）落地

文档 §4.4 定义了 `add_tag` 动作但没有标签载体，第一版仅写审计留痕；经人工确认（§10.4）后新增：

- 模型：`Tag`（全局/组作用域、7 种配色、启用开关，作用域内同名唯一）、`TicketTag`（工单↔标签，记录来源与操作人，同一工单同一标签唯一）；
- 服务：`resolve_tag` / `add_tag`（幂等）/ `remove_tag` / `tags_available_for` / `ticket_tag_names`；
- 规则动作：命中 `add_tag` 规则时真正落库（`source="rule"`），与 `set_status`/`assign_user` 共用一条 `rule_action` 审计；
- 界面：工单详情打标签/移除、收件箱按标签筛选与展示、`/routing/tags/` 标签字典维护、Django Admin 同步注册；
- 演示数据：`seed_demo` 会创建 4 个标签与一条「主题含紧急 → 打标签紧急」的规则；
- 权限与业务规则全量设计（权限矩阵、L1–L15 规则清单、生命周期边界、场景走查、巡检 SQL）：见 `docs/标签权限与业务逻辑设计.md`；
- 关键不变量：作用域内同名唯一（全局标签由应用层兜底、判重大小写不敏感）、同一工单同一标签唯一（幂等）、跨组专属标签不可用（服务层闸门）、单工单上限 20（**被拒请求不留孤立标签**）、改派后原组标签保留为历史标签。

## 5. 交付过程中发现并修复的问题（自验证记录）

以下问题都是在实现/验证阶段真实暴露出来的，均已修复并补了回归用例：

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | `Rule.matches` 直接用 `msg.get("Subject")` 比较 | RFC2047 编码的中文主题**永远无法命中规则** | 匹配前统一 MIME 头解码（`decode_mime_header`），补 `tests/test_routing.py` 回归 |
| 2 | 归并用的 Message-ID 未归一化 | IMAP 重投/UIDVALIDITY 变化时会**重复建单** | 入库与比对都做 `strip("<>")`，新增 `test_pipeline_deduplicates_same_message_id`、`test_sync_is_incremental` |
| 3 | 附件下发与 Nginx `alias` 的路径映射不一致 | 生产环境附件 **404** | 统一为 `X-Accel URI = 前缀 + 数据库相对路径`，alias 指向媒体根目录，并把不变量写进配置注释与安全报告 |
| 4 | 收件箱对非法查询参数（`?group=abc`）直接过滤 | 页面 **500** | 安全转换 + 忽略非法值，补 9 个参数健壮性用例（含 SQL 注入串） |
| 5 | `Mailbox.get_fallback()` 对脏配置直接 `int()` | 一条脏配置导致**所有无邮箱组无法发信** | 改用 `Setting.get_optional_int` 并回退到 `is_fallback` 标记 |
| 6 | 审计 CSV 导出未防公式注入 | 客户可控内容在 Excel 中被当公式执行 | `_csv_safe()` 中和 `= + - @` 开头单元格，补 `tests/test_audit_export.py` |
| 7 | 邮件头/正文编码边界、`cid:` 内联图片、`Expression` 型 CSS | 乱码或 XSS 绕过 | 解析层做编码回退 + surrogate 修复；净化层整体删除危险标签、CSS 属性过滤 |
| 8 | 账号界面创建的超级管理员没有 `is_staff` | 导航里的 Django Admin 入口是死链 | 勾选 `is_superadmin` 时同步 `is_staff`/`is_superuser`；补 `tests/test_account_admin_flow.py` |
| 9 | 账号表单未接入密码校验器、改自己密码会被踢下线 | 弱密码可入库；操作体验差 | 接入 `AUTH_PASSWORD_VALIDATORS` + `update_session_auth_hash` |
| 10 | CI 中硬编码了测试用 Fernet 密钥 | 密钥出现在版本库，易被误认为生产密钥 | 改为每个作业用 `openssl`/`Fernet.generate_key()` 现场生成 |
| 11 | **附件内联预览的存储型 XSS**（独立验证发现）：HTML/SVG/XHTML 附件被当作 `inline` + 原始 MIME 返回 | 外部发件人可在客服点击"预览"时于应用同源执行脚本（读 csrftoken、代发同源请求） | 预览改为白名单类型（图片/纯文本/PDF）；活动内容与未知类型只能下载；响应强制 `nosniff` + `CSP: default-src 'none'; sandbox`，并使用白名单 MIME 而非原始 MIME |
| 12 | 危险扩展名尾部点/空格绕过（`tool.exe.`、`tool.exe `） | Windows/浏览器保存后会变成 `.exe`，预览闸门被绕过 | `normalized_filename` 剥离控制字符与尾部空格/点后再判定 |
| 13 | `Setting` 缓存跨用例泄漏（测试隔离缺陷） | 前一个用例写入的配置值污染后续用例，可产生假绿/假红 | 根 `conftest.py` 增加 autouse `cache.clear()`；粘性用例显式设定窗口值 |
| 14 | 粘性窗口 `N=0` 时 `last_message_at == now` 仍判粘性 | 关闭粘性的意图无法表达 | 仅当 `window_days > 0` 才启用粘性，并补边界用例 |
| 15 | `docs/安全清单核查.md` 把 `DATA_UPLOAD_MAX_MEMORY_SIZE` 当成文件大小上限 | 文档过度声明（该设置只统计非文件字段） | 更正为"表单层 + 存储层校验文件大小，Nginx `client_max_body_size` 兜住请求体"，并说明 Django 的实际语义 |
| 16 | X-Accel 用例断言的是实现自身公式 | 无法发现"前缀 ↔ Nginx alias"配置漂移 | 改为按 Nginx `alias` 规则换算后与磁盘真实文件比对，并新增读取 Nginx 配置的漂移守卫用例 |

## 6. 建议的后续迭代（非阻塞）

1. 规则正则加超时/长度限制（ReDoS 理论风险，当前仅捕获 `re.error`）。
2. `pipeline` 目前对同一封邮件解析两次（保持文档接口形态的代价），可在高吞吐场景合并。
3. 富文本内嵌图片上传尚未接入（当前用附件承载文件）；如需内嵌可复用附件存储 + 一个上传端点。
4. 若要把 `/media/` 全部收口，可把内嵌图片也迁到 `attachments/` 并统一走 X-Accel-Redirect。
