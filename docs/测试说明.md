# 测试说明

## 1. 运行方式

```bash
cd /srv/ticket-system/app
# 安装依赖（首次）
uv venv --python 3.12 .venv && .venv/bin/python -m pip install -r requirements-dev.txt
# 或：python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt

# 全量测试（默认 SQLite 内存库，离线运行）
.venv/bin/python -m pytest -q

# 只跑第 12 节验收用例
.venv/bin/python -m pytest tests -q

# 带覆盖率
.venv/bin/python -m pytest --cov=apps --cov-report=term-missing -q

# Django 自检（含迁移完整性）
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
```

`pytest.ini` 已固定 `DJANGO_SETTINGS_MODULE=config.settings` 与 `testpaths = apps tests`。

**测试不依赖本地 `.env`**（CI 里根本没有这个文件）：

- `UNDER_TEST` 为真时，`config/settings.py` 会强制 `SECURE_SSL_REDIRECT=False` 并关闭
  Secure Cookie / HSTS——否则 Django test client 的每个 `http://testserver` 请求都会先被 301 到 https，
  让"未登录跳 302 / 越权 403"这类断言全部失配（CI 上真实踩到过）；
- `SECRET_KEY` / `FERNET_KEY` 在 `DEBUG` 或测试环境下有确定性派生兜底，生产环境没有兜底
  （缺 `SECRET_KEY` 直接拒绝启动，缺 `FERNET_KEY` 由 `deploy_check` 判 FAIL）。
  因此本地 `rm .env && python -m pytest` 也应当是 510 全绿。

## 2. 离线策略

- 所有测试都不访问网络：
  - SMTP 出口 `apps.mailboxes.services.smtp_send` 被 `tests/conftest.py` 的 autouse fixture 拦截，
    已发邮件收集在 `outbox` fixture 中（断言 From/Reply-To/主题/线程头）。
  - IMAP 同步（`apps/mailboxes/sync.py`）在测试中通过 monkeypatch 替换或在断言异常路径时使用；
    管理命令测试用 `--once` + 打桩 `sync_all_mailboxes`。
- 附件写入 `tmp_path`（`settings.MEDIA_ROOT` 被覆盖），不污染仓库的 `media/`。

## 5. MariaDB 集成测试（上线前必做）

单元测试跑 SQLite（§10.2）。上线前用真实 MariaDB 复跑一遍，验证字符集、索引长度与 JSON 字段：

```bash
export DB_ENGINE=mysql DB_HOST=127.0.0.1 DB_PORT=3306 \
       DB_NAME=ticket_system_test DB_USER=ticket DB_PASSWORD=*** \
       DJANGO_SECRET_KEY=*** FERNET_KEY=***
.venv/bin/python manage.py migrate
.venv/bin/python -m pytest -q
```

预期差异：`Mailbox` 的"全局唯一兜底"与"全局唯一模板"在 MariaDB 上由应用层
`clean()/save()` 保证（数据库不支持带条件的唯一索引，详见 `docs/需求实现对照.md` DEV-4）。
