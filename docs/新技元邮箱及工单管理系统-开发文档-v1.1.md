## 1. 项目概述

一套自部署的多用户共享邮箱与工单管理系统。连接飞书企业邮箱的 SMTP/IMAP，将统一对外邮箱与各用户组专用邮箱的来信转为工单，按规则路由到用户组，支持组内协作、组身份发信、自动回复、改派、审计，最终形成一个对客户统一、对内分工明确的邮件工单闭环。

**核心特征：**

- 统一邮箱 + 组邮箱 + 全局兜底邮箱，三个层级对外。
- 工单按主题路由到组，短期粘性、长期重路由。
- 对外以组身份发信，对内记录实际发件人。
- 组内共享可见，认领可选，待回复标签驱动协作。
- 全链路审计，权限模型清晰。

## 2. 需求规格（冻结版）

### 2.1 邮箱与入口

| 邮箱类型 | 对外公开 | 用途 |
|---|---|---|
| 统一邮箱 | 是 | 首次进线入口，按主题路由到组 |
| 组专用邮箱 | 是 | 该组对外收发信身份，客户可直接发入 |
| 全局兜底邮箱 | 是 | 无邮箱组发信时使用，全局唯一 |
| 管理员组邮箱 | 是 | 管理员组的对外身份 |

- 允许组没有对外邮箱，只做权限容器。此类组的工单回信走全局兜底邮箱。
- 所有邮箱通过 SMTP/IMAP 连接飞书企业邮箱。

### 2.2 工单生成与路由

| 场景 | 行为 |
|---|---|
| 发到统一邮箱，能归并已有工单 | 归并原工单，保持原组，不重新路由 |
| 发到统一邮箱，不能归并 | 按主题规则路由到组 |
| 发到组邮箱，能归并已有工单 | 归并原工单。工单号优先于收件人 |
| 发到组邮箱，不能归并 | 直接进入该组 |
| 多规则命中 | 按优先级，第一个命中即停 |
| 未命中任何规则 | 指定兜底组优先，没有兜底组才进管理员池 |
| 改派 | 任意组可改派到任意组；原组默认失去可见性（超管/管理员组除外）；写入审计 |
| 改派后客户回复 | 归并原工单，保持新组归属 |

**工单号校验**：通过 `[T#123]` 匹配到工单时，必须校验发件人与该工单 `customer_email` 一致。不一致视为新工单，不归并。

### 2.3 粘性规则

- **短期粘性**：同发件人在 N 天内再次进线，归原组。N 由管理员配置，基准是 `last_message_at`。
- **长期无粘性**：超过 N 天，按主题重新路由。
- **同工单内回复**：永远保持原组，不重新路由。

### 2.4 自动回复

- **统一邮箱**：首次进线 + 非自动邮件 + 非退信 + 非批量邮件 → 发一次。
- **组邮箱**：首次进线也发，内容可单独配置。
- **首次进线判断**：未归并到任何已有工单，且同发件人 N 小时内无新建工单。N 由管理员配置。
- **模板**：全局一套 + 组可覆盖。
- **模板变量**：工单号 `[T#123]` 等。
- **自动回复本身也记录**：写入 `messages`，标记 `is_auto_reply=True`。
- **防循环过滤**：见 6.1。

### 2.5 发信与审计

- 对外 `From` 和 `Reply-To` 都用组邮箱；无邮箱组用全局兜底邮箱。
- 内部记录实际发件人，对外身份为组邮箱。
- 主题带工单号 `[T#123]`，作为归并 fallback。
- 归并优先级：`References` / `In-Reply-To` > 主题工单号（且校验发件人）。
- 审计：谁、何时、以哪个组身份、给哪个客户、发了什么。

### 2.6 组内协作

- 组内工单默认共享可见。
- **待回复标签**：客户来信打上 → 有人回复消失 → 客户再回再打上。状态记在 `tickets.is_awaiting_reply`。
- **认领**：可选；认领后认领人看到"待回复"，其他人看不到；不认领也可以，谁回谁回，回复不自动认领；无论是否认领，组内所有人都能看到工单。
- 历史工单保留原组归属，不因人员调整丢失。

### 2.7 用户与权限

- 每个成员独立服务账号密码。
- 一个用户可在多个用户组。
- 超级管理员和其他人一样，只是同时在多个组，并在管理员组里。
- 管理员组是一个用户组，有对外邮箱，同时是权限容器，可跨组查看。
- 超级管理员可在所有用户组，并调整用户组。

### 2.8 内容

- 支持附件收发。
- 支持富文本。

### 5.1 工单归并

```python
# apps/tickets/services.py

import re


def extract_email(header_value: str) -> str:
    """从 '张三 <a@b.com>' 提取 a@b.com。"""
    match = re.search(r"<([^>]+)>", header_value or "")
    if match:
        return match.group(1).strip().lower()
    return (header_value or "").strip().lower()


def find_ticket(msg, mailbox):
    """
    归并优先级：
    1. References / In-Reply-To，校验发件人
    2. 主题工单号 [T#123]，校验发件人
    返回 Ticket 或 None。
    """
    sender = extract_email(msg.get("From", ""))

    # 1. References / In-Reply-To
    refs = (
        (msg.get("References", "") or "")
        + " "
        + (msg.get("In-Reply-To", "") or "")
    ).split()
    for mid in refs:
        m = Message.objects.filter(message_id=mid).first()
        if m and m.ticket.customer_email == sender:
            return m.ticket

    # 2. 主题工单号，必须校验发件人
    match = re.search(r"\[T#(\d+)\]", msg.get("Subject", "") or "")
    if match:
        ticket = Ticket.objects.filter(id=int(match.group(1))).first()
        if ticket and ticket.customer_email == sender:
            return ticket
        # 发件人不匹配 → 视为新工单

    return None
```

### 5.2 路由引擎

```python
# apps/routing/services.py

from datetime import timedelta
from django.utils import timezone


def route_ticket(msg, sender, mailbox, now=None):
    """
    返回应归属的 Group。
    优先级：粘性 > 规则 > 兜底组 > 管理员组。
    """
    now = now or timezone.now()

    # 1. 粘性判断，基于 last_message_at
    window_days = int(Setting.get("sticky_window_days", 7))
    last = (
        Ticket.objects
        .filter(customer_email=sender)
        .order_by("-last_message_at")
        .first()
    )
    if last and last.last_message_at >= now - timedelta(days=window_days):
        return last.group

    # 2. 规则匹配，按优先级，第一个命中即停
    rules = (
        Rule.objects
        .filter(mailbox=mailbox, enabled=True)
        .order_by("priority")
    )
    for rule in rules:
        if rule.matches(msg):
            group = rule.resolve_group()
            if group:
                return group

    # 3. 兜底组
    fallback_group_id = Setting.get("fallback_group_id")
    if fallback_group_id:
        group = Group.objects.filter(id=fallback_group_id).first()
        if group:
            return group

    # 4. 管理员组
    return Group.objects.filter(is_admin_group=True).first()
```

### 5.3 自动回复

```python
# apps/autoresponder/services.py

from datetime import timedelta
from django.utils import timezone


def should_auto_reply(ticket, sender, now=None):
    """
    首次进线判断：
    - 未归并到任何已有工单
    - 同发件人 N 小时内无新建工单
    """
    if ticket is not None:
        return False

    now = now or timezone.now()
    window_hours = int(Setting.get("first_contact_window_hours", 24))
    return not Ticket.objects.filter(
        customer_email=sender,
        created_at__gte=now - timedelta(hours=window_hours),
    ).exists()


def send_auto_reply(ticket, mailbox):
    """
    发送自动回复，并记录为 messages.is_auto_reply=True。
    """
    template = resolve_template(mailbox)
    body = render_template(template, {"ticket_id": ticket.id})

    msg = build_mime(
        from_addr=mailbox.email,
        reply_to=mailbox.email,
        to_addr=ticket.customer_email,
        subject=f"[T#{ticket.id}] {ticket.subject}",
        body_text=body,
        headers={"Auto-Submitted": "auto-replied"},
    )
    smtp_send(mailbox, msg)

    Message.objects.create(
        ticket=ticket,
        mailbox=mailbox,
        direction="out",
        type="message",
        from_addr=mailbox.email,
        to_addr=ticket.customer_email,
        subject=msg["Subject"],
        body_text=body,
        is_auto_reply=True,
        sent_at=timezone.now(),
    )


def resolve_template(mailbox):
    """
    模板解析：组覆盖 > 全局。
    """
    if mailbox.group:
        tpl = Template.objects.filter(
            scope="group", group=mailbox.group
        ).first()
        if tpl:
            return tpl
    return Template.objects.filter(scope="global", group__isnull=True).first()
```

```python
# apps/tickets/utils.py

import re


def normalize_subject(subject: str) -> str:
    """剥离 Re:/Fwd:/回复:/转发: 等前缀，并去掉工单号。"""
    s = subject or ""
    pattern = r"^\s*((re|fwd|fw|回复|转发|答复)\s*[:：]\s*)+"
    prev = None
    while prev != s:
        prev = s
        s = re.sub(pattern, "", s, flags=re.I)
    s = re.sub(r"\[T#\d+\]", "", s)
    return s.strip()
```

### 6.1 防循环过滤

```python
# apps/mailboxes/filters.py

import re


def is_loop_mail(msg) -> bool:
    """
    命中任一条件直接丢弃或标记为系统通知：
    - 不生成工单
    - 不触发自动回复
    """
    auto = (msg.get("Auto-Submitted", "") or "").lower()
    if auto in ("auto-generated", "auto-replied"):
        return True

    if (msg.get("X-Auto-Response-Suppress", "") or "").lower() == "all":
        return True

    if (msg.get("Precedence", "") or "").lower() in ("bulk", "junk", "list"):
        return True

    if msg.get("List-Id"):
        return True

    sender = extract_email(msg.get("From", ""))
    if Mailbox.objects.filter(email=sender).exists():
        return True

    if re.match(r"^(no-?reply|mailer-daemon|postmaster)@", sender, re.I):
        return True

    return False
```

自己发出的自动回复必须带 `Auto-Submitted: auto-replied`，形成对称防护。

```python
# apps/mailboxes/sync.py

from imapclient import IMAPClient


def sync_mailbox(mailbox):
    """
    增量拉取指定邮箱的新邮件。
    每个邮箱独立调用，由 APScheduler 定时触发。
    """
    secret = decrypt(mailbox.secret_encrypted)

    with IMAPClient(mailbox.imap_host, port=mailbox.imap_port,
                    ssl=mailbox.imap_ssl) as client:
        client.login(mailbox.username, secret)
        client.select_folder("INBOX")

        # 检查 UIDVALIDITY，变了则重置 last_uid
        uidvalidity = client.folder_status("INBOX")[b"UIDVALIDITY"]
        if uidvalidity != mailbox.uidvalidity:
            mailbox.last_uid = 0
            mailbox.uidvalidity = uidvalidity
            mailbox.save(update_fields=["last_uid", "uidvalidity"])

        uids = client.search(["UID", f"{mailbox.last_uid + 1}:*"])
        if not uids:
            return

        for uid, data in client.fetch(uids, ["RFC822"]).items():
            raw = data[b"RFC822"]
            process_inbound(mailbox, uid, raw)

        mailbox.last_uid = max(uids)
        mailbox.save(update_fields=["last_uid"])
```

### 6.5 入站处理主流程

```python
# apps/mailboxes/pipeline.py


def process_inbound(mailbox, uid, raw_bytes):
    """
    单封邮件的处理流水线。
    """
    msg = parse_mime(raw_bytes)

    # 1. 防循环
    if is_loop_mail(msg):
        return

    # 2. 解析
    sender = extract_email(msg.get("From", ""))
    subject = msg.get("Subject", "") or ""
    normalized = normalize_subject(subject)
    body_text, body_html = extract_body(msg)
    body_html = sanitize_html(body_html)
    attachments = extract_attachments(msg)

    # 3. 归并
    ticket = find_ticket(msg, mailbox)

    if ticket is None:
        # 新建工单
        group = route_ticket(msg, sender, mailbox)
        ticket = Ticket.objects.create(
            mailbox=mailbox,
            group=group,
            subject=subject,
            normalized_subject=normalized,
            customer_email=sender,
            last_message_at=timezone.now(),
        )

    # 4. 写消息
    message = Message.objects.create(
        ticket=ticket,
        mailbox=mailbox,
        message_id=msg.get("Message-ID", ""),
        in_reply_to=msg.get("In-Reply-To", ""),
        references=msg.get("References", ""),
        direction="in",
        type="message",
        from_addr=sender,
        to_addr=msg.get("To", ""),
        cc_addr=msg.get("Cc", ""),
        subject=subject,
        body_text=body_text,
        body_html=body_html,
        sent_at=parse_date(msg.get("Date")),
    )
    for att in attachments:
        Attachment.objects.create(message=message, **att)

    # 5. 待回复标签
    on_inbound(ticket)

    # 6. 自动回复
    if should_auto_reply(ticket, sender):
        send_auto_reply(ticket, mailbox)
```

### 8.1 MariaDB 注意事项

- **字符集**：数据库、表、连接全部用 `utf8mb4`，否则中文和 emoji 会出问题。
- **Django 驱动**：用 `mysqlclient`（推荐）或 `PyMySQL`。
- **JSON 字段**：MariaDB 10.2+ 支持 JSON，Django 的 `JSONField` 可用。
- **全文搜索**：Django 的 `full-text search` 深度绑定 PostgreSQL。MariaDB 上搜索用 `LIKE` 或原生 `MATCH...AGAINST`。MVP 阶段用 `LIKE` 即可，量大再优化。
- **索引长度**：`utf8mb4` 下索引键长度有限制，`CharField(max_length=500)` 加索引可能报错。需要索引的字段控制在 `max_length=191` 以内，或用前缀索引。

## 10. AI 开发规范与约束

AI 编码助手在本项目中扮演"执行力强的初级开发"。约束方式如下：

### 10.1 模型先行

- 所有业务不变量优先编码到 Django Model 里：外键、`UniqueConstraint`、`null=False`、`choices`。
- AI 生成代码时，模型关系会自动约束它的写法，减少逻辑错误。
- 禁止在视图层用 `if/else` 重复校验模型已经保证的约束。

### 10.2 测试约束

- 核心逻辑必须有单元测试，覆盖第 12 节的用例。
- AI 修改代码后必须先跑测试再提交。
- 测试要快：用 `pytest-django`，SQLite 跑单元测试，MariaDB 跑集成测试。

### 10.3 安全审查清单

AI 生成的代码提交前，人工检查：

- [ ] `DEBUG = False`，`ALLOWED_HOSTS` 不是 `['*']`
- [ ] `SECRET_KEY` 和 `FERNET_KEY` 来自环境变量，未硬编码
- [ ] 无裸 SQL 字符串拼接
- [ ] 无 `eval()` / `exec()`
- [ ] 无 `subprocess(shell=True)`
- [ ] 所有视图有 `@login_required` 或 DRF 的权限类
- [ ] 用户输入经过 `sanitize_html` 再入库
- [ ] 文件上传有类型和大小校验
- [ ] 邮箱凭据加密存储，日志里不出现明文

### 10.4 禁止事项

- 禁止 AI 自行修改 Model 字段，需人工确认。
- 禁止 AI 自行新增第三方依赖，需人工确认。
- 禁止 AI 修改 `settings.py` 的安全相关配置。
- 禁止 AI 在 `migrations/` 下手写迁移文件。

### 10.5 提交约定

- 每个功能一个 commit。
- commit message 格式：`[模块] 简述`，如 `[tickets] 实现工单归并逻辑`。
- 每个 commit 必须附带对应测试。
